# v42.0-36 — Zigbee cover control over low-power hybrid UART (BENCH ONLY)

## Basis and measured RX baseline
The new experiment is based on **v42.0-35**, which the user tested for **2645 seconds (44:05)**: 962 valid Tuya frames, 0 parser rejects, 3 software framing errors, 0 UARTE hardware errors, 0 UART handoff errors, 962 UART wakeups, 12,823 EasyDMA bytes of 13,827 RX bytes, and Zigbee LQI 153. `uart_test_phase=7` remained active past 1200 s. The user's earlier **v42.0-34 idle current** was 0.04–0.05 mA; v42.0-36 current is not yet measured.

## Hardware and isolation
- nRF52840 **P0.17 GPIO/TIMER3 + UARTE0 RX**: Tuya P3 motor **TXD** -> nRF P0.17, common GND.
- nRF52840 **P0.20 UARTE1 TX**: nRF P0.20 -> Tuya P3 motor **RXD**, common GND. This connection was **absent** during all RX-only v42.0-35 measurements and must be installed for commands to reach the motor.
- Signal pins are **3.3V UART TTL**, not RS232. Never bridge 5V or battery supply pins. Power off before soldering; verify continuity and no short to GND/adjacent pads before powering on.
- UARTE1 is an **independent hardware peripheral** on nRF52840. Its Zephyr UART driver is disabled. Direct-register EasyDMA TX sends a single queued frame; UARTE1 immediately stops and is disabled after sending. TX pin idles high (UART mark). This means there is **no need to disable or reassign UARTE0 RX during commands**.
- v42.0-35 code `src/p3_soft_uart.c` was not modified. Its software detection of first `55`, UARTE0 EasyDMA receive, GPIO rearming and ~15-ms idle STOPRX remain identical.
- The Zigbee radio uses TIMER2; receive code uses TIMER3. Independent UARTE1 TX is not a timer-based software UART.

## Supported explicit Zigbee commands
- Window Covering **OPEN**, **CLOSE**, **STOP**: Tuya classic `0x06` DP1 commands generated by the existing encoder tested in v41.3.
- Window Covering **GO_TO_LIFT_PERCENTAGE** (0..100%): Tuya classic DP2 encoded by the existing `tuya_motor_encode_position()` path.
- STOP purges queued future commands; transmission already in progress is allowed to finish.
- No automatic commands at boot, after Zigbee rejoin, or in response to MCU reports; no retries.
- **Disabled:** MCU startup requests, hardware motor calibration, local calibration TX and periodic queries.
- Commands are acknowledged as **queued**, not necessarily executed by the motor. Physical movement/DP acknowledgments must be checked.
- No optimistic position updates: reported ZCL lift position only follows actual MCU DP3 reports.
- Battery ZCL value follows MCU DP13 only when a syntactically valid report is received; it may remain **N/A**, as no ADC measurement exists.

## Hybrid RX state to Zigbee
The same continuous reader in `main.c` now calls:
- `tuya_uart_note_rx_byte()`: atomic RX byte count without per-byte mutex.
- `tuya_uart_accept_report(&decoded)`: pass complete Tuya frame through `tuya_motor_apply_report()` (only valid classic MCU command 0x07) into position/motion/battery state; schedule ZCL updates on Zigbee thread when actual values change.
- `tuya_uart_set_rejected_count(parser.rejected)`: diagnostic rejected count.
- After the 30-sec receive start and successful `p3_soft_uart_start()`, `tuya_uart_set_rx_ready(true)` unblocks explicit command queue.

## Mandatory hardware test stages
1. Preserve **v41.3** working motor firmware and **v42.0-35** RX baseline. Check **green GitHub Actions** and valid UF2. This new branch has not been hardware validated.
2. Disconnect power, wire the TX signal only as shown above, confirm no shorts; allow motor to move without interference.
3. Boot test HW-954. Wait for `uart_test_phase=7`, `uart_rx_ready=1`; check Zigbee remains paired and motor does not move spontaneously. Confirm current in quiet state and compare to the old measured 0.04–0.05 mA *baseline* (not a promise).
4. First send only **STOP** from Zigbee2MQTT. Check `zigbee_motor_commands` increments and `tx_frames` increments by one, with no unexpected motion. Compare `tx_failed_bytes=0`.
5. With a physical STOP method available, request **OPEN** briefly, then **STOP**; later CLOSE then STOP. Verify expected direction, manual STOP operation, correct DP1/DP3 reports and no RX UART regression.
6. Only after directional behavior is verified, request **50%** as a supervised DP2 test and verify the actual motor reports DP3. Do not assume percent is physically calibrated.
7. Monitor `uart_handoff_errors`, `uart_hardware_errors`, RX rejects, Zigbee LQI and active/idle current. Check `stress_elapsed_s>1200`, phase stays `7`.
8. If unexpected movement, TX timeouts, Zigbee dropout, rising RX errors, or excess current: stop testing, disconnect motor TX wire with power off, and revert to v42.0-35.
